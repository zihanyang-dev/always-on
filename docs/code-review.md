# 代码审查经验

## 阅读调用处与实现

- 从真实入口走一遍正常流程和失败路径。核对接口的输入、输出、状态所有者以及调用方需要记住的顺序。
- 逐个审查受影响的函数和回调，覆盖应用、测试、脚本和迁移入口。顺着函数读输入、卫语句、关键操作、结果。并列的注册有清楚的间隔，查询后的判断紧跟查询。
- 优先看主线是否连贯。编排函数用逻辑段落呈现准备、执行和收尾。提取函数时，检查它能否表达独立意图、集中一条规则或封装资源状态。
- 同类型的位置参数容易传反。调用处需要同时辨认两个身份、路径或游标时，用具名对象表达。
- 注释解释事务的锁顺序、外部调用的确认条件或资源为什么按这个顺序关闭。改规则时同时核对实现、调用处、注释和测试。
- 删除失去调用者的路径。把仍有价值的回归迁到正式入口，减少读代码时遇到的重复版本。

## 审查事务和资源生命周期

- 从用户操作确定事务范围。依赖同一个状态作判断和提交的步骤，在同一个事务中完成。对同一批资源建立固定加锁顺序。
- 用调用方能理解的动作命名事务入口。具体查询可以由对应资源的操作负责，并接收调用方持有的事务。
- 可能等待锁的检查结束后，重新核对有时效的权限或租约。拒绝过期尝试的更新，用尝试身份或版本保护状态，使用已有标识即可表达时优先复用。
- 外部调用已发生、调用已失败、结果暂时未知需要各自的结果语义。重试前按能确认的事实决定是否会重复副作用。
- 让资源的所有者处理取消、排空和释放。在执行收尾与传输关闭各有约束时，分别设置等待策略并报告失败。

## 自动化检查与行为测试

- 用 lint 执行确定的语法约束和依赖方向。新增规则时，用一个允许的例子和一个应拦截的例子验证它的作用范围。
- 模块的职责、阅读顺序和接口深度由人审查。参数数和文件行数可以提示复查，提取的依据仍是独立职责和调用约束。
- 验证并发时显式控制两个请求的同步点，等到可观察的状态再释放阻塞。断言前收尾并等待所有参与的异步任务。
- 依赖数据库锁、SDK 收尾或断线语义的回归，选能观察实际行为的测试边界。测试资源集中释放，并让意外错误进入测试结果。
- 交付记录写清实际运行的检查及其范围。类型、lint、单元测试和真实链路分别提供不同证据。
