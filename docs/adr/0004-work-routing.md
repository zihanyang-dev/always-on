# 0004 工作归属与执行交接

Work 持有用户交办的目标、上一次保存的进度，以及与外部讨论的绑定。用户可以通过消息明确发起工作或继续已有工作。外部讨论按 Workspace、连接和讨论 ID 寻址。同一个绑定键只能指向一项工作，一项工作可以关联多个讨论。绑定接口的讨论 ID 最多 1,000 个 UTF-16 代码单元，UTF-8 编码后最多 2,400 字节，以匹配 PostgreSQL 索引键容量。

Worker 领取 Inbox 事件后，核对用户当前的 Workspace 权限或读取已有讨论绑定。Work 在同一个事务中校验租约、记录归属、为已分配的事件保存执行请求，然后确认 Inbox 完成。归属未定的事件留下 `needs_routing` 决策。以后 Router 可以通过平台校验提交归属建议。

同一项工作的执行请求按入队顺序领取，一次只有一个有效租约。完成请求和保存进度在同一个事务内提交。后一轮可读取前一轮已提交的进度。领取进程退出后，请求仍在数据库里，到期可以重新领取，旧令牌无法提交。

API 和 Inbox Worker 分别启动。当前 Worker 消费 Inbox 并提交执行请求，执行端通过 Work 的领取和完成接口衔接。集成测试以可控执行结果验证同一项工作从等待到再次执行，以及进程退出后的租约恢复。
