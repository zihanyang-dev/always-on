# ADR-0004：功能内聚的工程目录与分属各自所有者的配置

状态：已采用目录与配置归属原则，基础工程已搭建；完整产品能力仍在后续阶段实现。日期：2026-11-14。

延续 Web、后端、CLI 三个交付物，后端 API/Worker 共用功能模块，先仅提取协议契约与 Agent 运行适配两个共享包。选择按功能集中规则、事务和接入，公共底层能力独立维护；接受功能模块包含多种技术实现，避免多套技术分层使一次修改跨大量目录。具体目录见 [工程设计](../project-structure.md)。

部署配置由进程入口解析，产品设置由 PG 中的对应功能管理，单次运行记录已解析输入，本机偏好归客户端。用户凭据加密保存，运行记录引用凭据；部署密钥由部署系统提供。放弃把模型、授权与用户连接统统塞入全局 env/config 包的方式，因为它会把可编辑、多用户、有版本的产品状态绑到进程重启上。

Web 优先同源 API，部署时需要变化的公开配置通过独立白名单返回；构建 env 仅用于公开的构建参数。代价是维护一个小型公开配置契约，收益是同一前端产物可部署到多个环境，后台密钥也不进入前端构建路径。配置解析、默认值、覆盖权限和生命周期均按上述所有者验收，不建立通用动态配置框架。
